# Penjelasan Milestone M03 — Transaksi Peminjaman & Pengembalian

## Apa yang dibuat
- `app/Http/Requests/PeminjamanRequest.php`: FormRequest validasi input transaksi peminjaman.
- `app/Services/PeminjamanService.php`: Service class yang membungkus pemanggilan stored procedure `sp_buat_peminjaman`, `sp_tambah_detail_pinjam`, dan `sp_kembalikan_peminjaman` di dalam `DB::transaction()`.
- `app/Http/Controllers/PeminjamanController.php`: Controller penanganan form Peminjaman Baru, penyimpanan transaksi, daftar pengembalian, dan konfirmasi pengembalian.
- `routes/web.php`: Pendaftaran rute transaksi peminjaman dan pengembalian dengan middleware level `operator`.
- `resources/views/peminjaman/create.blade.php`: Halaman antarmuka Peminjaman Baru lengkap dengan Tom Select lokal dan modal tambah cepat peminjam.
- `resources/views/peminjaman/pengembalian.blade.php`: Halaman antarmuka pengembalian barang.

## Kenapa dibuat begini
- Menggunakan stored procedure database (`sp_buat_peminjaman`, `sp_tambah_detail_pinjam`, `sp_kembalikan_peminjaman`) untuk memastikan aturan bisnis stok dan validasi transaksi dijalankan langsung di level database.
- Menggunakan Tom Select dari folder lokal `public/vendor/` agar aplikasi tetap berjalan offline tanpa CDN.

## Alur kode
1. Operator membuka halaman Peminjaman Baru -> Controller mengambil daftar peminjam aktif dan view stok inventaris (`v_stok_inventaris`) -> merender `peminjaman.create`.
2. Operator memilih peminjam, tanggal, dan barang serta jumlah -> submit form -> `PeminjamanRequest` memvalidasi input -> `PeminjamanService` memanggil stored procedure di dalam database transaction -> transaksi tersimpan dengan status `dipinjam`.
3. Operator membuka halaman Pengembalian -> Controller menampilkan daftar transaksi aktif -> operator menekan tombol "Kembali" -> `sp_kembalikan_peminjaman` dijalankan, mengubah status menjadi `kembali` dan memulihkan stok.

## Cara menguji
| No | Langkah | Hasil yang diharapkan |
|---|---|---|
| 1 | Operator membuka menu Peminjaman Baru | Form peminjaman tampil dengan dropdown peminjam dan barang. |
| 2 | Memasukkan jumlah barang melebihi stok tersedia | Sistem menolak dengan pesan error dari stored procedure. |
| 3 | Menyimpan transaksi pinjam | Transaksi tersimpan dan stok barang berkurang otomatis. |
| 4 | Operator membuka menu Pengembalian | Daftar peminjaman aktif tampil dan dapat dikonfirmasi kembali. |

## Pertanyaan yang mungkin muncul saat ujian
- **Q:** Bagaimana perhitungan stok tersedia dipastikan akurat saat peminjaman?
  **A:** Menggunakan fungsi database `fn_stok_tersedia` dan view `v_stok_inventaris` yang menghitung total jumlah inventaris dikurangi total detail pinjam berstatus `dipinjam`.

## Contoh modifikasi yang mungkin diminta
- **Modifikasi:** Menambah batasan maksimal jumlah barang per item pinjam.
- **File yang diubah:** `app/Http/Requests/PeminjamanRequest.php`.
