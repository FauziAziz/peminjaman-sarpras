# 2.1.5 Database Management System (DBMS)

Dalam aplikasi pencatatan peminjaman sarpras sekolah ini, pengelolaan basis data menggunakan MySQL sebagai Database Management System (DBMS) relasional. MySQL dipilih karena kestabilannya dalam menangani operasi basis data transaksional menggunakan mesin penyimpanan InnoDB yang mendukung *ACID (Atomicity, Consistency, Isolation, Durability)* serta penerapan aturan integritas referensial antar tabel.

## Peran DBMS dalam Sistem Peminjaman
DBMS bertanggung jawab untuk menyimpan, mengamankan, dan mengatur akses data induk maupun data transaksi harian petugas. Seluruh aturan integritas data diterapkan langsung pada tingkat basis data untuk mencegah inkonsistensi, antara lain melalui:
1. **Foreign Key dengan Aturan `RESTRICT`**: Memastikan data master seperti kategori, ruang, atau barang yang sudah terikat pada transaksi peminjaman tidak dapat dihapus secara sembarangan oleh pengguna.
2. **Indeks Unik (Unique Index)**: Mencegah duplikasi data entitas seperti nomor induk petugas atau duplikasi barang dalam satu nomor bukti pinjam.

## Penggunaan Stored Procedure dan Fungsi
Selain tabel standar, sistem ini mengandalkan *Stored Procedure* dan *Stored Function* di dalam MySQL untuk memproses logika bisnis yang kritikal secara terpusat:
- **`fn_stok_tersedia(id)`**: Fungsi basis data untuk menghitung sisa stok barang secara real-time berdasarkan total kuantitas dikurangi jumlah barang yang sedang berstatus `dipinjam`.
- **`sp_buat_peminjaman` dan `sp_tambah_detail_pinjam`**: Prosedur untuk menangani pembuatan transaksi dan validasi ketersediaan stok secara atomik di dalam blok transaksi basis data.
- **`sp_kembalikan_peminjaman`**: Prosedur untuk memproses pengembalian barang dan memulihkan stok inventaris secara otomatis.

Pendekatan ini menjamin bahwa seluruh batasan validasi dijalankan secara ketat oleh basis data, mengurangi beban logika pada lapisan aplikasi, serta menjaga keandalan pencatatan inventaris sekolah.
