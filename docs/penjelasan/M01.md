# Penjelasan Milestone M01 — Setup Database, Auth/Login, & Layout Base AdminLTE

## Apa yang dibuat
- `database/migrations/2026_11_11_000001_create_peminjaman_sarpras_tables.php`: Membuat 8 tabel utama (`level`, `petugas`, `kategori`, `ruang`, `inventaris`, `peminjam`, `peminjaman`, `detail_pinjam`) dengan FK `RESTRICT` dan unique index anti-duplikat.
- `database/migrations/2026_11_11_000002_create_stored_procedures_and_views.php`: Membuat fungsi `fn_stok_tersedia`, view `v_stok_inventaris`, dan stored procedures (`sp_buat_peminjaman`, `sp_tambah_detail_pinjam`, `sp_kembalikan_peminjaman`, `sp_riwayat_peminjaman`).
- `database/seeders/DatabaseSeeder.php`: Mengisi data awal level, akun admin (`admin`), akun operator (`operator`), kategori, ruang, inventaris, dan peminjam.
- `app/Models/`: Model Eloquent (`Level`, `Petugas`, `Kategori`, `Ruang`, `Inventaris`, `Peminjam`, `Peminjaman`, `DetailPinjam`) dengan primary key dan table name eksplisit.
- `config/auth.php`: Mengarahkan auth provider ke model `Petugas`.
- `app/Http/Middleware/CekLevel.php`: Middleware untuk memeriksa level hak akses (`admin` / `operator`).
- `bootstrap/app.php`: Mendaftarkan alias middleware `level`.
- `lang/id/validation.php`: Pesan validasi FormRequest berbahasa Indonesia.
- `app/Http/Requests/Auth/LoginRequest.php`: FormRequest validasi otentikasi login.
- `app/Http/Controllers/Auth/LoginController.php`: Controller penanganan form login, proses authentikasi, dan logout.
- `app/Http/Controllers/DashboardController.php`: Controller dashboard dengan statistik per role.
- `routes/web.php`: Rute web untuk autentikasi dan dashboard dengan proteksi middleware.
- `resources/views/layouts/auth.blade.php` & `resources/views/layouts/app.blade.php`: Layout utama AdminLTE 4 lokal (tanpa CDN).
- `resources/views/auth/login.blade.php`: Halaman antarmuka login.
- `resources/views/dashboard/index.blade.php`: Halaman dashboard ringkasan statistik.
- `resources/views/components/tabel-otomatis.blade.php` & `public/js/tabel-otomatis.js`: Komponen reusable tabel dan modul JS pencarian server-side.

## Kenapa dibuat begini
- Menggunakan AdminLTE 4 dari `public/vendor/` tanpa CDN agar aplikasi dapat berjalan offline sesuai ketentuan ujian.
- Autentikasi berbasis username pada tabel `petugas` sesuai PDM P3.
- Pemisahan hak akses menggunakan middleware level kustom (`CekLevel`) untuk membatasi rute admin dan operator secara ketat.

## Alur kode
1. Pengguna membuka `/login` -> `LoginController@create` merender `auth.login`.
2. Pengguna mengisi username & password -> `LoginRequest` memvalidasi input -> `Auth::attempt` memeriksa kredensial pada tabel `petugas`.
3. Jika berhasil, sesi diregenerasi dan diarahkan ke `/dashboard` -> `DashboardController@index` menyiapkan statistik berdasarkan level user (`admin` atau `operator`) -> merender `dashboard.index`.
4. Jika mencoba mengakses rute dengan level yang tidak sesuai, middleware `CekLevel` menolak dengan HTTP 403.

## Cara menguji
| No | Langkah | Hasil yang diharapkan |
|---|---|---|
| 1 | Buka `http://peminjaman-sarpras.test/login` | Tampil halaman login AdminLTE 4. |
| 2 | Login dengan username `admin` / password `password` | Masuk ke Dashboard Admin dengan statistik data induk. |
| 3 | Login dengan username `operator` / password `password` | Masuk ke Dashboard Operator dengan statistik transaksi. |
| 4 | Akses `/dashboard` tanpa login | Di-redirect ke halaman login. |

## Pertanyaan yang mungkin muncul saat ujian
- **Q:** Mengapa autentikasi memakai tabel `petugas` alih-alih tabel `users` bawaan Laravel?
  **A:** Sesuai PDM P3, tabel login petugas bernama `petugas` dengan primary key `id_petugas` dan field `username`.
- **Q:** Bagaimana mencegah operator mengakses halaman admin?
  **A:** Menggunakan middleware `CekLevel` (`level:admin` / `level:operator`) yang membandingkan nama level user dengan parameter route.
