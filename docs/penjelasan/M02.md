# Penjelasan Milestone M02 — Kelola Data Induk

## Apa yang dibuat
- `app/Http/Requests/*Request.php`: FormRequest validasi untuk Petugas, Kategori, Ruang, Inventaris, dan Peminjam dengan pesan error Bahasa Indonesia dan aturan anti-duplikat.
- `app/Services/*Service.php`: Service classes untuk menangani logika bisnis data induk, pengecekan FK sebelum penghapusan data, dan penomoran kode barang otomatis.
- `app/Http/Controllers/*Controller.php`: Resource controllers untuk Petugas, Kategori, Ruang, Inventaris, dan Peminjam.
- `resources/views/*`: Tampilan Blade untuk indeks, form tambah, dan form ubah data induk menggunakan komponen `x-tabel-otomatis`.
- `routes/web.php`: Pendaftaran rute CRUD data induk dengan pembatasan hak akses middleware `admin` dan `operator`.

## Kenapa dibuat begini
- Validasi dua lapis (FormRequest + Unique Index DB) menjamin integritas data tidak duplikat.
- Pemisahan logika bisnis ke Service layer menjaga Controller tetap tipis dan mudah diuji.

## Alur kode
1. Pengguna mengakses menu data induk -> Controller mengambil data dengan paginasi dan filter pencarian -> merender view terkait.
2. Pengguna menyimpan/mengubah data -> FormRequest memvalidasi input -> Service memproses penyimpanan atau update database -> diarahkan kembali dengan pesan sukses/error.

## Cara menguji
| No | Langkah | Hasil yang diharapkan |
|---|---|---|
| 1 | Admin menambah Kategori/Ruang dengan kode/nama duplikat | Form menolak dan menampilkan pesan error validasi duplikat. |
| 2 | Admin menghapus Kategori/Ruang/Barang yang berelasi dengan transaksi/inventaris | Ditolak dengan pesan jelas bahwa data masih digunakan. |
| 3 | Operator membuka menu Peminjam | Dapat melihat daftar peminjam dan tombol tambah, tanpa tombol ubah/nonaktifkan. |

## Pertanyaan yang mungkin muncul saat ujian
- **Q:** Bagaimana mencegah penghapusan data kategori yang sudah terpakai barang?
  **A:** Diperiksa melalui method di `KategoriService` yang mengecek relasi inventaris sebelum menghapus.
